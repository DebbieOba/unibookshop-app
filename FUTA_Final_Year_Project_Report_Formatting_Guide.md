# Final Year Project Report — Formatting and Styling Guide

## 1. Overall Document Setup

| Element | Recommended Setting |
|---|---|
| Paper size | A4 |
| Orientation | Portrait |
| Main font | Times New Roman |
| Body font size | 12 pt |
| Chapter headings | 14–16 pt, Bold, UPPERCASE |
| Section headings | 12–14 pt, Bold |
| Subsections | 12 pt, Bold |
| Line spacing | 1.5 lines |
| Paragraph alignment | Justified |
| First-line indent | 0.5 inch / 1.27 cm |
| Paragraph spacing | 0 pt before, 6 pt after |
| Left margin | 1.5 inches / 3.81 cm |
| Right margin | 1 inch / 2.54 cm |
| Top margin | 1 inch / 2.54 cm |
| Bottom margin | 1 inch / 2.54 cm |
| Page numbers | Bottom centre or bottom right |
| Body text color | Black |
| Heading color | Black |

> **Important:** If your department or FUTA has an official project-writing guideline, follow it over these general recommendations.

## 3. Chapter Heading Style

Chapter headings should be visually distinct from ordinary section headings.

Recommended format:

**CHAPTER THREE**

**SYSTEM ANALYSIS AND DESIGN**

### Chapter heading settings

- Font: Times New Roman
- Size: 14–16 pt
- Bold
- Uppercase
- Centre aligned
- Black
- Leave approximately 2–3 blank lines before the first section

Example:

```text
CHAPTER THREE

SYSTEM ANALYSIS AND DESIGN

3.1 Introduction
```

---

## 4. Section Heading Style

Example:

### 3.5 System Requirements

Recommended settings:

- Font: Times New Roman
- Size: 12 pt
- Bold
- Left aligned
- Black
- No underline
- No decorative colors

Avoid excessive styling such as:

- `3.5 SYSTEM REQUIREMENTS!!!`
- Underlined headings
- Colored headings
- Italicized headings without a reason

Keep the hierarchy clean and consistent.

---

## 5. Paragraph Formatting

Recommended body-text settings:

- Font: Times New Roman
- Font size: 12 pt
- Alignment: Justified
- Line spacing: 1.5
- First-line indentation: 0.5 inch / 1.27 cm
- Paragraph spacing: 0 pt before and 6 pt after

Example:

> The development of digital platforms has significantly changed the way university services are delivered. Traditional university bookshops often rely on manual processes for inventory management, product identification, ordering, and record keeping. These processes can result in delays, inaccurate records, and difficulties in monitoring available resources.

### Avoid

Do not manually create spacing using multiple spaces or repeated Enter presses.

Use:

- Paragraph settings
- Margins
- Indentation
- Tabs
- Styles

This is especially important for the Table of Contents and page numbering.

## 6. Page Numbering

Use two numbering systems.

### Preliminary Pages

Use Roman numerals:

```text

iii
iv
v
vi
vii
```

The title page usually has no visible page number.

### Main Chapters

Start Arabic numbering from Chapter One:

```text

3
4
5
...
```

Recommended structure:

| Section | Numbering |
|---|---|
| Title Page | No visible number |
| Declaration | ii |
| Certification | iii |
| Dedication | iv |
| Acknowledgement | v |
| Abstract | vi |
| Table of Contents | vii |
| List of Figures | viii |
| List of Tables | ix |
| Chapter One | 1 |

## 7. Figures and App Screenshots

Because this is a software/app project, screenshots are an important part of the documentation.

Do not paste screenshots randomly. Every figure should have:

1. A figure number
2. A descriptive caption
3. A reference in the body text
4. An explanation where necessary

### Recommended format

```text
             [SCREENSHOT OF LOGIN PAGE]

             Figure 4.1: User Login Interface
```

### Figure settings

- Caption font: Times New Roman
- Size: 10–12 pt
- Centre aligned
- Caption placed below the figure
- Number figures according to the chapter

For Chapter Four:

- Figure 4.1
- Figure 4.2
- Figure 4.3
- Figure 4.4

For Chapter Five:

- Figure 5.1
- Figure 5.2

### Example explanation

> Figure 4.1 illustrates the login interface of the developed application. The interface allows registered users to provide their credentials before accessing the system.

Use descriptive captions such as:

**Figure 4.1: User Login Interface**

Avoid captions such as:

**Screenshot 1**

---

## 8. Tables

Tables should also be numbered by chapter.

Example:

**Table 3.1: Functional Requirements**

| Requirement | Description |
|---|---|
| User Registration | Allows users to create accounts |
| Login | Authenticates registered users |
| Search | Allows users to search for products |
| Ordering | Allows users to place orders |

### Table recommendations

- Table caption should normally appear above the table.
- Use consistent borders.
- Avoid unnecessary colors.
- Keep table text readable.
- Do not split a table unnecessarily across pages.
- Refer to important tables in the body text.

Example:

> Table 3.1 presents the major functional requirements of the proposed system.

---

## 9. Color Scheme

The main academic report should be predominantly black and white.

### Recommended

- Body text: Black
- Headings: Black
- Tables: Black/grey
- Diagrams: Project-specific colors may be used
- Screenshots: Preserve the original application colors

Avoid:

- Red paragraphs
- Blue body text
- Green section headings
- Purple page numbers
- Excessive decorative colors

Your application's brand colors can be retained in:

- UI screenshots
- System architecture diagrams
- Flowcharts
- Interface diagrams
- Other project-specific illustrations

The written report itself should remain formal and restrained.

---

## 10. Font Selection

The safest academic font for the main report is:

**Times New Roman**

Recommended hierarchy:

| Element | Font Size | Style |
|---|---:|---|
| Body text | 12 pt | Regular |
| Section heading | 12 pt | Bold |
| Subsection | 12 pt | Bold |
| Chapter heading | 14–16 pt | Bold |
| Figure caption | 10–12 pt | Regular |
| Table caption | 10–12 pt | Regular |
| Footnotes | 10 pt | Regular |
| References | 12 pt | Regular |

Avoid mixing many fonts.

For example, do not use:

- Poppins for chapter headings
- Times New Roman for body
- Arial for tables
- Calibri for captions

A consistent font system looks much more professional.

## 11. Justification and Alignment

Use different alignment depending on the element.

| Element | Alignment |
|---|---|
| Body paragraphs | Justified |
| Chapter headings | Centre |
| Section headings | Left |
| Figure captions | Centre |
| Table captions | Centre or Left |
| Title page | Centre |
| References | Left / hanging indentation |

### Body text

Use **justified alignment** so that the text forms clean left and right edges.

### Chapter headings

Use **centre alignment**.

### Section headings

Use **left alignment**.

## 12. Abstract

The abstract should provide a concise overview of the entire project.

Unless your department specifies otherwise, approximately **200–300 words** is a reasonable target.

The abstract should cover:

1. The problem
2. The aim of the project
3. The methodology
4. The system developed
5. Major results
6. Conclusion

Recommended style:

- Times New Roman
- 12 pt
- 1.5 line spacing
- Justified
- No screenshots
- No unnecessary bullet points

A good structure is:

**Problem → Method → System Developed → Results → Conclusion**

---

## 13. References

Use one referencing style consistently.

For an engineering/ICT project, **IEEE referencing** is a suitable option if it matches your department's requirements.

### IEEE example

```text
[1] J. Smith, Software Engineering: Principles and Practice,
4th ed. London, U.K.: Academic Press, 2024.
```

### In-text citation

```text
The use of automated systems can improve the efficiency of
organisational processes [1].
```

Do not mix citation styles.

For example, avoid using both:

```text
[1]
```

and:

```text
(Smith, 2024)
```

unless your required referencing style specifically calls for both.

Every diagram should have a figure number and caption.

## 15. Code in the Report

Do not paste the entire source code into the main chapters.

Instead:

- Show only important code snippets.
- Explain what each relevant snippet does.
- Put extensive source code in the appendices.

Example:

**Listing 4.1: User Authentication Function**

```text
[Relevant code snippet]
```

Long source code can be placed under:

**APPENDIX A: SELECTED SOURCE CODE**


## 18. Overall Professional Design Principle

Think of the report as having three visual layers.

### Layer 1 — Academic

- Black text
- Times New Roman
- Numbered chapters
- Formal language
- Consistent citations
- References

### Layer 2 — Structure

- Headings
- Subheadings
- Tables
- Figures
- Page numbers
- Table of Contents
- List of Figures
- List of Tables

### Layer 3 — Project-Specific Content

- Application screenshots
- System architecture
- Database diagrams
- UI designs
- Flowcharts
- Test results
- Relevant code snippets

The combination makes the report look like a professional **software engineering/final-year project report**, rather than a normal school essay.
